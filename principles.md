# Principles

## Contributors add value by being cognitively engaged



## Work must be teachable, not ineffable "taste"



## Teams succeed together

Maximizing individual output doesn't translate to team success.

## Production codebases must stay maintainable

While there are surely *some* ways we could update our idea of what's maintainable based on our new options, there is a dangerous *misconception* that code quality has become irrevelant.

Code is communication. When we say that code is **readable**, that means that code snippets make it more likely to draw correct conclusions by looking at them. Given that agents need a clear context and code is part of the context, it should be intuitively obvious why they are more accurate with maintainable code.

There are now at least 6 agent benchmarks that show maintainability effects over time: SlopCodeBench, EvoClaw, SWE-CI, SWE-Chain, SWE-Interact, ContextRotBench.

## Usable abstractions are intentionally designed


## Tools are for people to use, not compete with

Components of a system are not meant be "better" than eachother, they are meant to work well together. For instance, a tool that does part of a job should make clear what part remains to be done.

## Consent matters (right of refusal)

The software we want is made *for* us or *with* us. It's not done *to* us.

The consent-erasure of "inevitability" deprives users of leverage to make sure the implementation meets their needs.
